## Web 多插件统一登录方案（设计讨论定稿）

- 统一登录口径收敛在 `web/backend/app.py` 网关：`/api/auth/callback` 唯一回跳 + `spb_session` Cookie（HttpOnly）+ `require_auth` 统一校验 + 服务端静默刷新 refresh_token。
- 分工口诀：前端带 session（Cookie），网关管 token，上游服务端验 token。插件前后端零登录代码。
- 前端统一入口：单 Vue 应用多路由起步；多机部署用 Nginx 反代收口（同一 Cookie 域 + `/api/*` 指向唯一网关）；跨子域需 Cookie 加 `Domain=父域`；完全不同域名会破坏口径（需 SSO/重设计）。
- 登录失效跳转：前端只从 `/api/auth/me` / `/api/auth/login-url` 现取 loginUrl（含实时 nonce/PKCE），配合请求拦截器捕获 401 跳转；callback 需支持 `redirect` 参数回跳原插件页（待实现）。
- 已识别待办：① 抽 `web/backend/auth.py` 认证模块；② `SESSIONS` 内存字典需外置（多实例/重启丢失）；③ callback 固定跳 `/` 需支持 redirect；④ callback 里 `SESSIONS.get(sid,...)` 取 target_client 恒为 None 的小 bug。
- 部署形态结论：认证网关 + 会话存储 + Nginx 入口必须集中；插件业务后端/前端可分布式（LAN 可达即可），生产再迁常驻服务器。

## authorize 400 根因确认（redirectUrl 白名单）

- 报错链路：前端 → webapi `_resolve_iam_login_url` → 服务器 `/api/user/auth/authorize` 400 `redirectUrl not in allow list`。
- 实测白名单语义：host 严格匹配 localhost / 127.0.0.1（任意端口路径、http/https），局域网 IP（172.23.x/192.168.x）与服务器自身域名一律 400，无通配。
- 结论：白名单是为本地 client loopback 回调设计的；多设备经 172.23.123.73 访问时 base_url 拼出的回跳必然被拒，**必须改服务器白名单**（建议：私网 IP 放行或 SPB_EXTRA_REDIRECT_HOSTS 环境变量），服务器代码不在本机。
- client login.py 回跳恒为 http://localhost:{port}，不受影响。
- 顺手修：web/backend/app.py `_resolve_iam_login_url` 加 HTTPError 分支透传服务器 400 响应体；webapi 镜像已后台重建。

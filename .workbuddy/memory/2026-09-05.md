## 2026-09-05（晚） Vue 前端重写版（web/，替代此前 src/smartplaybuddy/web 静态版——该目录现已不存在）

- 用户新需求：改用 Vue 实现；无登录页（本前端即统一登录验证成功后的跳转 url，复用已有登录验证）；仅 daily_task 完整执行 + 清体力；清体力计划 0-30（=×10 开拓力）；提供星穹铁道功能的 API 供测试。
- 新增 `web/`（与 src/smartplaybuddy/web 静态旧案无关）：
  - `backend/app.py`（FastAPI，端口 8765）：`/api/auth/callback` 接收统一登录回跳（accessToken/refreshToken/expiresIn，与 user/login.py 契约一致）→ 内存会话 + HTTP-only Cookie `spb_session`；过期自动 refresh；REST API（见下）；托管 `frontend/dist` SPA 回退。
  - `backend/bridge.py`：每指令临时 WS 连接（type=mod, deviceName=starrail-web-bridge）→ `mod:{uid}:starrail`，按 RequestID 等响应；Mod 的 event 进度收集进 job.events。短操作同步（ping/driver-ping/status/power/query/observe），长操作后台 Job 轮询 `GET /api/jobs/{id}`（daily_task/clear_power/reward）。⚠️ 帧必须用项目 Message 类（Data Base64），不能手拼 JSON。
  - `frontend/`（Vue 3 + Vite，已 npm install + build 到 dist）：App.vue 认证门（未登录显示"前往统一登录验证"→ SERVER_HOST authorize?redirectUrl=本服务/api/auth/callback）；DailyTaskPanel（观察/勾选 2·9·10/完整执行/仅领奖）；ClearPowerPanel（滑杆 0-30、类型 1/2/3、use_reserve、体力查询）；JobProgress 轮询进度。
- 测试 API：POST /api/starrail/ping|driver-ping|daily-task|daily-task/reward|clear-power{powerNum 0-30,selection 1-3,useReserve}；GET /api/starrail/status|power|daily-task/observe|operations|jobs/{id}；POST /api/starrail/execute 通用入口；POST /api/starrail/target-client。
- 冒烟验证通过：307 回调建会话、auth/me 返回 loginUrl 与 userId、powerNum=31 → 422、jobs 404、静态页 200。（Git Bash curl 对重定向响应有 exit 23 的假警报，勿误判）
- 启动：`python web/backend/app.py --port 8765`（fastapi/uvicorn 在 workbuddy venv 已有）；前端改动后 `cd web/frontend && npm run build`。文档：`web/README.md`。
- 登录回跳排查（18:54）：用户在 account.cabyss.cn 登录后未回到仪表盘；后端日志显示 `/api/auth/callback` 从未收到请求 → 断点在服务端 OAuth 回调→回跳之间。探测确认服务端 `/api/user/auth/callback` 活着（假 code 返回 500 oauth2 INVALID_CODE）。判断最可能是复用了旧 authorize 链接（state 里的 nonce 一次性/过期）。已给前端加 `?authError=` 可见报错并重新构建；等用户用新鲜链接重试后看最终 URL。授权 URL 中 state hex 解码即 {nonce, redirectUrl}。
- ✅ 真正根因（19:10 定位）：服务端 `{SERVER_HOST}/api/user/auth/authorize` 返回的是 **JSON `{"url": ...}` 而非重定向**（与 user/login.py 一致，需先解析 url 再打开浏览器）。此前前端直接把浏览器导航到该 authorize 端点 → 用户看到的是一段 JSON，从未到达登录页，回调自然收不到。修复：`app.py` 新增 `_resolve_iam_login_url()`，由后端代取真实 IAM 登录页地址（每次调用生成新 nonce/PKCE），`/api/auth/me` 与 `/api/auth/login-url` 均返回解析后的 url（附 ok/error 字段）；前端显示换取失败原因并重建。
- 端口冲突处理：用户自己在终端跑着旧代码实例（PID 18832，::1:8765，taskkill 拒绝访问无法终止）→ 修复版暂运行在 **8766**（后台任务）。用户应 Ctrl+C 停掉 8765 旧实例后重启加载新代码；redirectUrl 取自 request.base_url，端口自适应。

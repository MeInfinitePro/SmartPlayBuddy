## 2026-09-06 修复 daily_task 报 "Failed to read esc" 错误

- 根因：`DailyTask.py` 第 94/141 行误写 `pyautogui.click("esc")` —— click() 传字符串会把参数当作**待定位的图片文件**在屏幕上查找（pyscreeze 打开图像 "esc" 失败），报 "Failed to read esc because file is missing, has improper permissions, or is an unsupported or invalid format"。该分支位于"切换到每日实训界面失败"的兜底逻辑中。
- 修复：两处均改为 `pyautogui.press("esc")`；全项目 grep 确认无其他同类 `click("字符串")` 误用。
- 注意：驱动代码由 Client 进程加载，需重启 SmtPlay.Client 才生效（Python 模块已缓存）。

## 2026-09-06 Capture.py 截图链路改造（WGC 抗遮挡 + 窗口缓存）

- 背景：前端触发 daily_task 时图像识别"失效"且极慢。根因：`screen_capture` 用 `ImageGrab.grab(bbox)` 按屏幕矩形截图，游戏被浏览器遮挡时截到的是浏览器画面 → 模板全部匹配失败 → 每步定位吃满超时 + SIFT 兜底，总时长暴涨。
- 改造 `module/common/Capture.py`：
  1. 新增 `capture_window_content_wgc()`：Windows.Graphics.Capture API（依赖 `windows-capture` 包，Rust 绑定）。实测对 Unity 硬件渲染窗口有效（PrintWindow 被系统直接拒绝返回 0，ImageGrab 受遮挡影响），不受遮挡影响，约 200-600ms/次。
  2. 三级回退链：WGC → PrintWindow(`capture_window_content`，含纯色帧检测) → ImageGrab(旧行为)。
  3. 新增 `_get_cached_main_hwnd()`：缓存主窗口句柄，避免每次定位都 psutil 全进程扫描 + EnumWindows；locate.json 仅在窗口位置变化时写盘。
  4. `screen_capture` 接口不变（`sc(save_path)` 调用方无需改动）。
- requirements.txt 补充 pywin32、psutil、windows-capture。
- 实测：StarRail.exe 运行中（PID 5220，UnityWndClass 主窗口），WGC 抓取 1924x1140 std=57/101（真实画面），缓存后 399ms/次。
- 生效条件：Client 环境需 `pip install windows-capture`（Win10 1903+），并重启 SmtPlay.Client。

## 2026-09-06 locate.json 窗口位置改为实时获取（不缓存）

- 背景：用户要求窗口位置信息不用 locate.json 缓存，改为实时获取。
- 改动：
  1. `Locate.py` `get_actual_position()`：坐标换算不再读 `locate.json` 的 `last_window_position.rect`，改为 `_get_cached_main_hwnd()` + `get_window_rect_accurate()` 实时取窗口左上角（窗口移动后句柄不变，坐标即时更新）。
  2. `Capture.py` `screen_capture()`：删除「窗口位置变化时写 locate.json」逻辑；删除「无法获取窗口时删 locate.json」逻辑；`save_position` 参数保留作历史兼容（不再起作用）。
  3. `_get_cached_main_hwnd()` 与 `get_starrail_main_window()` 缓存校验新增 `not win32gui.IsIconic(hwnd)`，排除最小化窗口（最小化时 IsWindowVisible 仍为 True 但坐标移到 -16000 附近）。
- 实测发现：星铁道主窗口 hwnd=2102270 在某时刻处于最小化（iconic=1，rect=(-16000,-16000,...)），实时坐标换算正确返回 None。
- 注意：`get_starrail_main_window` 里 `position_manager`/`save_window_position`/`compare_with_last_position` 等 WindowPositionManager 相关代码仍保留但不再被 screen_capture 路径调用。

- 关键结论（下次直接可用）：
  1. 官方 SDK 仅 `sdk/Message.js` + `sdk/SmtplayWSBridge.js`，只有 send/recv/is_embedded，**没有 exit/close 方法**；`/sdk/SmtplayModBridge.js` 已 404（f3a73cd 把 ModBridge 重命名为 WSBridge，桌面 test.html 的 import 已过期）。我们 vendored 的副本与官方只差 import 路径。
  2. 平台控制台页 `src/views/ModConsoleView.vue` 用 `sandbox="allow-scripts allow-same-origin allow-forms"`——**无 allow-top-navigation**，iframe 内前端无法关闭/跳转父窗口；`src/composables/useWSBridge.ts` 只认 `__smtplay__` 信封（hello 握手 + payload 转发给 WS），**不解释任何 WS 消息**（全部原样 postMessage 回 iframe）。故纯前端做不到「退出」，必须平台侧配合。
  3. 平台自己的退出：`src/stores/auth.ts` + `src/utils/auth.ts` 的 logout() → POST `/api/user/auth/logout`（清 HttpOnly cookie + 撤 JTI），入口在 HomeView（`SmartPlayBuddy 控制台` 页头的「退出登录」）。
  4. ModConsoleView 里已有 `goBack()`（router.push home）与 `.back-btn` 样式但**模板没用上**——平台本就有加返回/退出按钮的意图。
- 拟定方案（未落地，改动已 git restore 撤销）：信封层约定控制消息 `{type:'system', action:'exit', data:{scope:'mod'|'platform'}}`；平台侧 useWSBridge 拦截（不转发 WS）→ onModExit 回调；ModConsoleView 按 scope 走 home 或 login（并 client.close()）。前端侧 platform.js 加 platformExit(scope)，api.js 平台模式 logout 调它。
